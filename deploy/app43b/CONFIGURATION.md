# Single-node offline deployment configuration

Files: source/deploy/app43b/application.template.json, render.py, network-preparation.json, initial-resource-profile.json, operator-scoped-rbac.json, operator-watch-patches.json, staged-admission.json and required-input-contract.json. Every proposed object is OFFLINE-NOT-FOR-APPLY. No kubectl/SSH live command was run.

Five app Deployments use dedicated automount=false SAs and exactly one Pod each. API is explicitly replicas1/Recreate, UID/GID1654/fsGroup1654, read-only rootfs, dropped capabilities, no privilege escalation and RuntimeDefault seccomp. Dedicated retained local RWO DP/uploads claims and read-only active/retired wrapping identities are distinct from ephemeral /tmp. No hostPath, RWX, extra API, HPA, public NodePort/LoadBalancer/Ingress or new component is introduced. All five Services are ClusterIP.

API startup/liveness use /health/live and readiness /health/ready; startup allows300seconds and dependency failure does not drive liveness restart. Baileys startup/liveness use /live and readiness /ready via Node HTTPS exec connecting to127.0.0.1 with explicit approved certificate servername/SNI and CA/SAN verification. This avoids a Service readiness cycle; three executed probe-option tests verify it. It is NOT a kubelet HTTPS probe falsely described as certificate-verifying. Its health CA mount and SAN must be owner-provisioned and tested. Original APP.3 Baileys plaintext HTTP image healthcheck still needs recipe correction in the separately authorized rebuild.

Per-consumer Redis data/Sentinel and Rabbit client identities are explicit read-only0440 Secret projections, configured through file-reference settings. ApplicationNamespace-local provisioned Secrets must contain workload identities, never backend CA/admin/operator private keys. Normalized mount filenames are a proposed configuration contract, not invented existing production file paths/credentials. Existing service namespaces/names/selectors are derived from APP.4.3A; see network-targets.json. Rabbit endpoint is the existing internal AMQPS5671 Service, Sentinel monitor is shopixy-redis-ha; owner-approved Secret connection strings must contain all3per-member Sentinel seeds and independent ACLs, not a guessed headless primary or old mymaster name.

Renderer rejects missing references, non-digest images, missing custody attestation and replicas other than1; explicitly projects all retained DP decryptors. Synthetic renderer output uses registry.invalid/zero digests and fixture references ONLY to validate shape; it is NOT a release manifest. It must never be deployed. Exact legacy ApplicationName is an owner-supplied ConfigMap reference, with no guessed default.

Network preparation retains existing policies and adds paired namespaceSelector AND podSelector paths: API ->PG5432/Mongo27017/Redis6379+Sentinel26379/Rabbit5671/Search9200/Baileys3000/DNS; Baileys ->Redis/discovery/DNS and API ingress. PG ingress additionally preserves data-cluster5432, cnpg-system8000 and monitoring9187. Because PG currently has no policies, applying any ingress selector would isolate it: validate all operator/backup/monitoring paths first. Do not apply PG isolation or egress default-deny by habit. Existing API server/B2/CA-revocation/payment/WhatsApp destinations, approved internal client/edge ingress and frontend egress need explicit scoped owner additions before live deployment. Current strict default-deny deliberately does not open global443 or publish an unapproved edge; those unresolved paths are a deployment gate, not hidden functional readiness.

Strict offline Kubernetes1.36 schemas and semantic/RBAC/renderer tests pass; schema-authorities.json binds exact schema versions/hashes. API-server CEL compilation, real admission and network packet enforcement are NOT EXECUTED. Owner must resolve all image/config/Secret/CA/decryptor/backup/endpoint inputs, validate a rendered release (including settings ConfigMaps and probes), and separately approve application. The preparation is concrete but is not falsely presented as an immediately applyable production bundle.
